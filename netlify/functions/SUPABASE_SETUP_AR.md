# إعداد بوابة Supabase على Netlify — لم يُنشر الموقع بعد

## الحالة الحالية

- مشروع قاعدة البيانات المقصود: `hanabila`، المعرّف `ssvrzhjefvqjrdpfvmhh`، وحالته عند التحقق `ACTIVE_HEALTHY`.
- سجل الترحيلات الحي يؤكد تطبيق `005_student_attendance_cas` إلى `012_student_excuses`. وظائف الأساس من `002`–`004` كانت موجودة قبل هذه الدفعة.
- جداول التطبيق الخاصة عليها RLS، ولا تمنح `anon` أو `authenticated` وصولًا مباشرًا. دوال التغيير المخصصة لا تُنفّذ إلا عبر `service_role` في بوابات Netlify.
- الواجهة والوظائف المعدلة باقية محليًا على `migration/supabase-auth`؛ لم يحدث push أو نشر Netlify أو تغيير للموقع الحي. اختبارات Node الحالية: **138 ناجحة**.

## متغيرات Netlify المطلوبة

على موقع staging مؤكّد فقط، عرّف المتغيرات التالية ضمن نطاق **Functions**:

- `SUPABASE_URL`
- `SUPABASE_PUBLISHABLE_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`

لا تضع `SUPABASE_SERVICE_ROLE_KEY` في المتصفح أو ملفات المصدر أو Git أو رسائل المحادثة. يجب أن يبقى سرًا خادميًا. لا تفتح سياسات RLS أو امتيازات الجداول لتجاوز عدم تهيئة الوظائف.

## مسار التحقق الآمن التالي

1. حدّد أي موقع Netlify هو staging غير إنتاجي أو أنشئ وجهة معاينة منفصلة؛ أسماء المواقع المتاحة لا تكفي لتحديد الإنتاج أو staging.
2. أضف متغيرات Supabase أعلاه في نطاق Functions للموقع غير الإنتاجي فقط.
3. انشر فرع النقل على staging، لا على `main` أو الموقع الحي.
4. اختبر بحساب طالب وقائد: تسجيل الدخول، تغيير كلمة المرور المؤقتة، استعادة الجلسة، الحضور، المهام والإثباتات، الاختبارات والتصحيح، الإجازات والأعذار ومرفقاتها، التحديات، الدردشة، والمنشورات والتعليقات والتفاعلات.
5. Web Push يعمل عبر VAPID وNetlify Functions، ولا يعتمد على Firebase؛ المرفقات الجديدة للأعذار والإجازات والمهام/الاختبارات تستخدم تخزينًا خاصًا وروابط موقعة قصيرة الأجل.
6. بعد نجاح staging ومراجعة خطة البيانات النهائية، حدّد نافذة القطع ثم اطلب نقل النسخة الحية.

## توصية Auth المتبقية

أشار مستشار الأمان إلى أن حماية كلمات المرور المسرّبة متوقفة. توضح [وثائق Supabase لأمان كلمات المرور](https://supabase.com/docs/guides/auth/password-security) أنها تُفعّل من إعدادات Auth في لوحة المشروع وتتطلب خطة Pro أو أعلى. جدول الأعذار الخاص يظهر في المستشار ضمن «RLS مفعّلة بلا سياسة»؛ هذا مقصود لأن الوصول المباشر ممنوع والبوابة الخادمية هي المسار الوحيد.

لا تُرسل كلمات المرور المؤقتة أو مفاتيح الخدمة في المحادثة، ولا تدمج إلى `main` أو تنشر إلى الإنتاج قبل اختبار المعاينة والتأكد من الوجهة.
